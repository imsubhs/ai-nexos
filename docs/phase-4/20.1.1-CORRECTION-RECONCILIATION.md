## 4. Gemini Model Reference Corrections

### 4.1 Investigation Findings
The identifier `gemini-3.8-flash` appears across 16 documents in the 20.1 documentation set (including `PRD.md`, `ROADMAP.md`, `AI_ARCHITECTURE.md`, `AI_GATEWAY.md`, `API_CONTRACT.md`, `SYSTEM_ARCHITECTURE.md`, `TRD.md`, `AI_SECURITY.md`, `TEST_STRATEGY.md`, and `IMPLEMENTATION_PLAN.md`).

Upon rigorous technical investigation:
1. **Actual Production Dependency?** **NO.** The current `server/` codebase contains zero external dependencies and zero network calls to Google Gemini API or any other foundation model. The AI seam in `server/oracle.mjs` operates entirely through the deterministic `LocalOracle`.
2. **Current Production GA Identifier?** **NO.** In the official Google Gemini API product line, model identifiers adhere to semantic release naming (e.g., `gemini-1.5-flash`, `gemini-1.5-pro`, `gemini-2.0-flash`). The identifier `gemini-3.8-flash` does not exist as a certified production GA endpoint.
3. **Architectural Anti-Pattern**: Hardcoding a specific model identifier into REST URLs (e.g., `https://generativelanguage.googleapis.com/v1beta/models/gemini-3.8-flash:generateContent`) directly couples the game's transport and domain contracts to a speculative external string.

### 4.2 Canonical Architectural Correction
1. **Status Update**: The specific model identifier is designated:
   ```text
   MODEL SELECTION — OPEN DECISION
   ```
2. **Provider Abstraction Mandate**: The application domain logic and WebSocket handlers **MUST NOT** reference or couple to any specific model identifier. All AI operations must interact strictly through the `IAiGateway` interface and its underlying `ModelProvider` abstraction:
   ```typescript
   export interface ModelProvider {
     readonly providerId: string;
     readonly modelId: string;
     generateStructured<T>(params: {
       systemPrompt: string;
       userPrompt: string;
       responseSchema: Record<string, unknown>;
       maxTokens?: number;
       temperature?: number;
       abortSignal?: AbortSignal;
     }): Promise<T>;
   }
   ```
3. **Runtime Configuration**: The actual model string must be supplied via runtime environment variables (e.g., `GEMINI_MODEL_ID` or `AI_GATEWAY_MODEL`), validated against an allowed provider schema at gateway initialization.
4. **Phase 20.2 Benchmarking Gate**: Final model selection is formally deferred to Phase 20.2, where candidate models will be benchmarked on:
   - Structured JSON schema adherence rate (zero syntax errors).
   - End-to-end response latency (P50, P95, P99).
   - Cost per 1,000 question generations.
   - Quality and tone adherence for relationship gameplay.

## 5. 3500ms Target/SLA Correction

### 5.1 Audit of Latency Claims
The values `3500ms`, `3.5 seconds`, or `3500 ms` appear across 15 documents in the 20.1 specification set, frequently labeled as an "AI Response Latency Target" or "Preferred SLA".

### 5.2 Evidence & Reality Check
- **Zero Empirical Telemetry**: The AI Gateway has not yet executed network requests against Google Gemini API from the game server runtime. No P50, P95, or P99 latency percentiles have been empirically recorded in production or staging.
- **Risk of Mischaracterization**: Treating 3500ms as an established "guarantee" would mislead architecture planning in 20.2 regarding timeout budgets, socket wait states, and player UX.

### 5.3 Mandatory Canonical Phrasing
All Phase 20.1 documentation is reconciled to enforce this exact phrasing:

> **3500ms is the current target/SLA threshold for the relevant AI operation; it is not an empirically certified production latency guarantee.**

### 5.4 Seven Benchmark Factors for Phase 20.2
Phase 20.2 is prohibited from treating 3500ms as a fixed constant until the following 7 latency components are empirically benchmarked:
1. **Upstream Inference Latency**: Time required by the LLM provider to generate tokens under strict JSON Schema constraints.
2. **Network Transit Duration**: Round-trip transit time between the game server host and the AI provider endpoint.
3. **Server Container Overhead**: Event loop latency, memory pressure, and GC pause times within the Node.js process.
4. **Prompt Token Volume**: Impact of few-shot exemplar count and player profile size on TTFT (Time to First Token).
5. **Schema Validation Time**: Duration of multi-tier in-process validation (JSON Schema, semantic checks, safety wordlists).
6. **Concurrent Load Degradation**: Latency degradation under 50, 100, and 500 simultaneous active rooms.
7. **Deadline Abort Execution**: Verified execution time required to trip the `AbortController` and substitute fallback static cards without dropping the client frame rate.

## 8. AI Authority Boundary

A primary constitutional invariant must be preserved across all specifications:

```text
    AI Candidate Output
            │
            ▼
    Multi-Tier Validation
  (Schema, Semantic, Safety, Rules)
            │
            ▼
   Authoritative Game Engine
  (Validates, Commits, Replaces)
            │
            ▼
   Deterministic State Transition
```

Under no circumstances may AI output mutate state directly:

```text
       AI Output  ───► [VIOLATION] ───►  State Mutation
```

### 8.1 Inviolable Prohibitions for Artificial Intelligence
The AI layer (including upstream models, the AI Gateway, Question AI, Personalization AI, and Report AI) is strictly prohibited from:
1. **Mutating Player Scores**: AI cannot award, deduct, or calculate points. All scoring logic is mathematically computed by `server/game.mjs`.
2. **Advancing Turn or Round State**: AI cannot trigger state transitions, advance round counters, or declare game over. State transitions belong exclusively to the Game Engine.
3. **Manipulating Game Timers**: AI cannot start, pause, extend, or terminate countdown timers. Timers are driven by server timestamps and client render clocks.
4. **Accessing Unrevealed Answers**: AI cannot be passed the active secret choice of a player during a round. The secret answer remains quarantined in the server's private round state.
5. **Deciding Answer Correctness**: AI cannot judge whether an answer matches or predict subjective correctness. Prediction evaluation is an exact integer index comparison (`hostChoice === guestChoice`).
6. **Assigning Player Seats or Roles**: AI cannot assign `host` vs. `guest` seats, determine turn ownership, or control player permissions.
7. **Bypassing Validation Gates**: AI output can never enter the game state without passing all 4 tiers of validation (Structural, Semantic, Safety, and Game Rule validation).
8. **Directly Emitting Socket Frames**: AI cannot write to WebSocket connections directly. All client frames are serialized and dispatched by the authoritative server protocol layer (`server/protocol.mjs`).

7. **Logging & Telemetry Redaction**: All structured server logs must automatically redact player names, answers, and raw prompts to prevent PII exposure in observability pipelines.

## 14. Resolved Decisions Register

The following architectural choices are formally certified as **DECIDED** and serve as immutable constraints for Phase 20.2:

1. **Game Engine Authority is Absolute**: The Game Engine (`server/game.mjs`) is strictly authoritative. AI is purely advisory and generative. AI cannot mutate game state, score answers, or manipulate timers.
2. **Deterministic Static Safety Floor**: The game must be 100% playable without external network calls or cloud AI services. Tier 1 static decks and the deterministic `LocalOracle` provide an inviolable fallback floor.
3. **Four-Tier Independent Validation**: Candidate AI outputs must independently pass: (1) Structural Schema Validation, (2) Semantic Validation, (3) Safety Validation, and (4) Game Rule Validation. Schema validity alone is never sufficient.
4. **Unary Structured JSON Contract**: All AI interactions must utilize unary request-response contracts with enforced RFC JSON Schemas. Streaming output is strictly prohibited for interactive question cards to prevent partial render leaks.
5. **Zero Secret Answer Leakage**: The predictor socket must receive zero bytes of information regarding the host's secret answer prior to simultaneous reveal.
6. **Fail-Closed Security & Instant Fallback**: Upon any upstream timeout, provider outage, or safety rejection, the engine must immediately fall back to deterministic static content without blocking the event loop or displaying spinners.
7. **Single-Instance Rate Limiting Baseline**: Abuse control follows the MemoryStore-first sliding window algorithm certified in Phase S6.7.
